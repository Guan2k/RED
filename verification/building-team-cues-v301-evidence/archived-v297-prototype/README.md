# RED 建筑阵营小标记：独立美工原型

此目录是以 v297 开发包为底的隔离原型，不是新版本，不替代 v298/v299 候选，也未发布。`RED/` 内保留原版本号与历史证据；这些历史证据不能当作本原型的验收结果。

## 本轮范围

- 仅指挥中心、发电站、精炼厂、战车工厂新增与车辆相同的小标记：己方双横条、敌方三角。
- 炮塔完全不加标记。概念中的固定底座标记会在炮口旋转至90°时完全遮挡，因此暂不采用。
- 沿用同一个默认关闭的外观预览选项。关闭分支、原造型、玩法、存储、碰撞尺寸及所有动态层保持原样。
- 标记6×4，衬底8×6；0.5×时只剩3×2像素，双横条各0.75像素高，可见性弱，不是无障碍保证。

## 独立验证与实际成本

`evidence/independent-stencil-verification.cjs` 与 `independent-stencil-results.json`：10,278条断言通过；覆盖450建筑组合、10类缓存/回退失败、16个全帧场景及重复绘制、末尾实体当前path检查、8地图各90秒world/RNG一致。包含双方四类、未变炮塔、施工/生产/选择/生命条层、默认关闭分支对等与无持久化。

方法计数包含save/translate/restore及measureText，不只fill：每个己方新增6次Canvas方法；敌方缓存新增5次，直接绘制新增10次；炮塔为0。四类双方各一座，共新增44次缓存方法或64次直接方法。几何缓存初始化额外1次构造和4次trace，总计20次构造/104次trace方法。它是调用计数，不是FPS测量。

若第一次失败恰好发生在敌方标记缓存fill，该次比原缓存建筑增加11次方法（指挥中心19→30，其余三类14→25）；之后锁存为直接绘制，每座比原直接绘制增加10次。若静态主体先失败，双方都增加一次失败调用，标记仍净增己方6/敌方10，不反复尝试失败缓存。

上下文的样式、变换、剪裁与栈精确恢复。必须特别说明：Canvas save/restore不保存当前path，直接绘制的敌方标记会留下三角形path；若最后实体为敌方电厂/精炼厂/工厂，该path可留到帧末。它不改变后续实际paint：本轮与下一帧均验证全部非标记paint/方法一致；指挥中心旗杆会重设path。不可把这描述成当前path完全恢复。

完整发行验收与原生浏览器验收未执行；请以本轮evidence为准，不使用复制包里的历史通过记录冒充本轮结果。

## 是否值得采用与解释边界

建议保留，等待v300之后的独立美工整合轮次评估采用。优势是四种较大建筑在原有颜色之外多一个与车辆一致的辅助识别线索；成本小而可数，但实际增加调用，绝不宣称性能提升。半尺寸读数弱，炮塔仍只有既有阵营配色与查看信息，因此它不是全类别识别保证。

四类有标记而炮塔无标记可能让第一次接触的人误以为“无标记=中立”或“无标记=另一队”。发布说明应明确“部分建筑新增辅助阵营标记：双横条为己方、三角为敌方；炮塔暂未添加。没有标记不代表中立或某一阵营”。不要称它为全单位阵营图标、统一全类别无障碍系统或取消颜色依赖。当前原型没有新增菜单/开关，也没有把这一解释误写进现有正式玩家指南。
