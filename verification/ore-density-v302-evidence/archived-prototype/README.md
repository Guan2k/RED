# 低余量矿点疏密概念（独立原型）

## 结论
值得作为下一轮候选：不增加新符号，只减少已有矿块，使低余量矿点在无遮挡时更稀疏。已检查中文 1× / 0.5× 对比和真实 render 指令重放。半尺寸时单块约 4.5×6 像素，疏密差仍可见；这是本次绘制样本的观察，不是玩家测试、原生像素验收、无障碍或 FPS 保证。

实际战场重放也显示：矿车可以完全遮住唯一矿块。保留底盘与数值标签仍能定位矿点；方案不保证遮挡时辨认。无需为保证可见而把矿块提到车辆或选择层上方。

## 模型与阈值
基于 final v301 vehicle-art-data。八地图初始化各矿点余量均为 12000；采矿目标布局仅移动位置。矿点仅有 x/y/amount，没有初始容量字段。存档接受 0 至 10000000 的有限数字，包括小数，不能用当前量除以虚构的“初始容量”。

本次人为选定绝对余量档位：
- >4500：保留 8 块。
- >1500 且 ≤4500：保留前 4 块。
- >0 且 ≤1500：保留第 1 块。
- ≤0：延续现有不绘制底盘/矿块/标签的行为。

块数不是金额、满载车次、储量百分比或可采时间。阈值只是视觉候选，没有经济平衡含义。1 块表示仍有矿，不能解读为耗尽。

标签和悬停说明完全保留：地图标签向上取整到 k，所以 1500 为“矿 2k”，1 和 180 都为“矿 1k”。精确值继续通过悬停查看（原有 Math.ceil 规则）。应在未来玩家说明写明“矿块疏密只表示余量粗档，以数值为准”。

## 范围与成本
仅改 renderer 的矿块循环上限；原矿块坐标、尺寸、交替颜色、33 半径底盘、标签位置/避让以及矿点交互/施工范围均不改。原有覆盖顺序不改，没有新增动画、设置、缓存、路径或实体字段。车辆/建筑美工开关不控制矿点，这个独立原型的粗档直接生效。没有引入任何已否决的炮塔标记。

每个未耗尽矿点原矿块部分 8 次 fillRect；中档减少 4 次，低档减少 7 次。没有额外 save/restore/translate 或路径调用。每帧只增加最多两次数值比较，且循环外求值。全帧成本与缓存等验证见 evidence，不能由调用减少推断原生帧率提升。

## 独立聚焦验证结果

42 组 / 7449 断言 / 144 次真实 render 对比通过。覆盖八地图开局与推进15秒、12个边界余量、旧画风/预览直接绘制/模拟缓存、连续帧、悬停/选择/暂停/施工/终局。仅应删除矿块的 fillRect 有差异；其余方法序列和绘图严格一致，world 与渲染 RNG 不变。方法总数包含 measureText、save/restore/translate 等，不把 fillStyle 属性赋值当方法。

混合余量 [1,1500,1500.1,4500,4500.1,0] 的覆盖层样本，模拟缓存完整帧 1071→1049（−22）；终局直接绘制 1440→1418（−22）。这些是指定夹具计数，不是原生性能数据。低、中、高各矿点分别减少7、4、0次 fillRect。
