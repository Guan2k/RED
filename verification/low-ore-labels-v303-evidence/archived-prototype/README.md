# 不足 1000 矿点标签：独立可读性原型

## 建议与范围
建议保留为下一版的窄变化候选。1× 样本中，原来统一的“矿 1k”变成可区分的“矿 1 / 矿 180 / 矿 999”，无需悬停即可获得较细的低余量信息。0.5× 字号仅5.5像素，读数仍弱；没有字号扩大或原生可读性保证。

基线为 final v302-ore-density/RED。只改变 oreLabelLayout 内 label 格式表达式：
- 0 < amount < 1000：`矿 ` + Math.ceil(amount)。
- amount ≥ 1000：保留 `矿 ` + Math.ceil(amount/1000) + `k`。
- amount ≤ 0：仍跳过整个矿点标签及绘制。

例如0.1→矿1、180→矿180、999.5→矿1000、1000→矿1k、1001→矿2k。仍向上取整，不能称为精确小数；999.5与1000在格式上有边界切换。块数8/4/1、颜色、半径、位置、悬停、经济、矿车、存档都不改。未升级显示版本，未写正式候选或GitHub，未发布。

## 布局和方法成本
每个新字符串继续进入原11px system-ui measureText路径，五个候选位置、边缘clamp、据点/范围文字/驻守目标避让和无安全候选时回退均未改。没有人为移动标签。字形宽度可以变长，也可变短，因此新标签可能换候选或在边缘向内移；不能承诺位置不变。

现有每帧字符串度量缓存按文本去重。以前1、180、999等都共用“矿1k”，现在可能产生更多不同文本，因此measureText方法调用可能增加。实际指令重放夹具中，其余记录方法均613次，measureText由4增至8，全方法617→621；paint均162次。这里的measureText使用原有VM合成宽度，不是系统字体实测。不能把“一处表达式”说成完全零成本，也不推断原生FPS。

原有布局不避让所有实体或矿点标签；全冲突回退仍可能重叠。单个矿块仍可能被矿车遮挡，Canvas文字也不自动具备屏幕阅读器或键盘浏览支持。本轮没有新增无障碍入口。

## 独立验证与具体布局变化
48项、11505断言、345个完整录制帧通过。覆盖八地图、阈值与小数、左右上下边缘、正字形extent、五候选和全部冲突回退、据点/范围文字/meridian上下标记四边的严格邻接、36/68半径切线。11个运行时负例被拒绝，包含旧低量规则、错误floor、包含1000的错误阈值、手工坐标偏移、忽略正左extent等。

以下只是显式注入的合成字体压力，不是本机或浏览器字体测量：
- widePositiveExtents：旧“矿 1k”width42/right53，新“矿 1000”width70/right81，left7/up19/down8。
- 矿点(1200,800)，余量999.5：旧标签(1143,788)，新(1115,788)，都使用候选0。增加宽度使原clamp向左移动28。
- meridian上方标记边缘矿点(510.000001,275.5)：旧标签(485.000001,323.5)，候选0；新标签(485.000001,201.5)，候选1。新宽度触发原避让算法换到上方。
- 据点左侧邻接矿点(503.000001,398)：旧候选0在(478.000001,446)，新候选3在(332.000001,402)。未放宽任何碰撞规则。

旧、新文本都按原方法测量；原有fallback冲突保留并明确验证，而非假称消除了所有重叠。≥1000的文本与布局原样保留。world/RNG、hover等非标签行为无变化。详见 evidence/independent-ore-label-results.json 与独立报告。

独立测试连续两次复跑JSON字节一致；见 evidence/REPRODUCIBILITY.json。另一个混合低量夹具全Canvas方法827→831，measureText11→15，paint266与fillRect185不变。与比较板夹具617→621是不同场景，不能混算。
